# nie: agent contract

nie is the self-hosted Inazuma Eleven engine and studio, and the home of all Rose Griffon Rust. It
loads game data from the installation the user owns. See `README.md` for the layout.

## Rules

- Rust 2024 workspace, one copy per crate. Every third-party crate comes from crates.io releases,
  versions read live (`curl -A nie https://crates.io/api/v1/crates/<name>`) and declared once in
  `[workspace.dependencies]`; members use `workspace = true`. No forks, no `[patch]`, no vendored
  third-party code. `cargo shear` stays clean (feature-only dependencies are listed in
  `[package.metadata.cargo-shear] ignored`).
- The only submodules are aphrody-labs/iecode-dotnet and iecode-cpp under `iecode/` (private,
  `update = none`, so public CI skips them): `git submodule update --init --checkout iecode/dotnet`.
- Never ship, copy or commit a game asset. Game data is read in place through `nie-assets`
  (`game://`) from a local path, SSH, or an rclone remote. Tests build synthetic fixtures in a temp
  directory.
- `contract/nie-app.json` and `contract/aphrody-store.toml` are generated by `nie-shell`; the test
  in `crates/nie-shell` fails when they drift.
- Heavy builds run on the build host (`ssh fr1`, `/srv/xbuild/nie`) or in CI. Commit by path on
  `main`, no AI attribution, check `gh run list -R aphrody-labs/nie` after pushing.
- Claude Code setup is generated: edit `tools/claude/profile.toml` (MCP servers, plugins, skills
  kept for nie) and run `bun ~/.claude/scripts/profile.ts` (the engine of aphrody-labs/claude, also
  re-applied at SessionStart); `--check` reports drift. `.mcp.json` starts the
  native `nie-mcp` server (local build, else the build host over SSH). Never hand-edit
  `.claude/settings.json`.
- nie is a standalone deployed service; consumers such as rosegriffon call it over HTTP and never
  embed its Rust.
- English, no emoji.
