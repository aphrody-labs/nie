# nie: agent contract

nie is a game engine and static/dynamic recompiler in Rust and the framework around it (`README.md` has the layout). OS, kernel, POSIX, AI and ML live in `fw`.
It is not a wiki: the wiki is one consumer. IEVR (Inazuma Eleven: Victory Road) is the first game on it;
`docs/specs/framework-layering.json` classifies every crate as framework or app and is the source of truth for
that split (`docs/specs/framework-layering.md` lists what is still mixed).

The IEVR app reads the installation the user owns through two artifacts: the game binary `nie.exe` (reverse
engineering: `nie index`, `rtti`, `disasm`, `mem`) and its data VFS (`data/cpk_list.cfg.bin`, the CPK archives it
lists, files under `data/common/*` and `data/dx11/*`). Every doc, typed table, CLI/MCP name and HTTP route derives
from those two; `nie --help`, `nie vfs stats` and `nie vfs formats` are authoritative, never facts written beside
them. Saves, the launcher with its mods, Steam and the reverse-engineering stack are plugins on top of that core.

Start from `MAP.tsv` (generated by `just map`) and `STYLE.md` (low-level Rust contract and agent method).

## Commands

`just` is the one human and CI entrypoint (`just` lists the recipes); `cargo xtask <sub>` (the `xtask/` crate) does
the work behind it, and every CI job is the recipe `ci-<job>` of the same name. lint, test, compile and check run on the
build host (`deploy/build.toml`; `NIE_BUILD_HOST`, `NIE_BUILD_DIR` override) when it answers, `--local` / `--remote`
force the choice, and `just fr1 <recipe>` runs any recipe there in a detached, logged tmux session. Heavy builds
and long commands run there or in CI, never on the PC; a missing tool is installed (pinned, `cargo binstall`), not worked around.

```sh
just check                  # fmt check, cargo check, bevy feature, drift tests
just lint [clippy|shear|secrets]   # clippy + shear + gitleaks
just fmt [--check]          # rustfmt + taplo
just test [--workspace] [--coverage]   # CI test job (nie-plugin: layering gate), or cargo llvm-cov per crate
just compile [--release] [--musl] [--windows] [--wasm] [--crlib] [--all]
just map [--check]          # MAP.tsv
just skill [--check]        # command, MCP tool and plugin table of the nie skill
just bindgen [--check]      # bindings/ (C, C++, Rust, Python, C#, Go, Bun, Zig) from a C ABI contract
just repro                  # two builds of HEAD in two directories, BLAKE3 of every artifact, writes docs/specs/repro-manifest.json
just ci-bindings            # smoke test of every binding against the cdylib
just ci-gui-linux           # GPUI toolkit snapshots and AccessKit audit (needs the sibling ../aphrody checkout and a Vulkan device)
just app-pack [out]         # the browser app bundle that nie-app embeds
just web-pack|web-serve|web-shot      # GPUI browser bundle, its server, headless Chrome proof
just deploy --host prd --bin-dir <dir>   # nie-deploy up: ship binaries + deploy/supervise.toml over nie-ssh, start the supervisor (no systemd unit, no container), wait for health
just fr1 <recipe>           # run a recipe on the build host in tmux, logged
cargo test -p nie-plugin --test layering   # framework crates name no game identifier and depend on no app crate
cargo run -p nie-shell -- contract > contract/nie-app.json   # regenerate the contract
cargo run -p nie-abi -- crates/nie-ffi                       # regenerate the C ABI layer of nie-ffi
nie deps audit --check      # process call sites and tracked crates against docs/research/log
nie plugins                 # the plugins of this build and the commands each one owns
nie new <app> --template cli|serve|lib|ui|wasm [--path DIR]   # scaffold apps/<app>, or an app anywhere, with its nie.toml
nie vfs lint                # parse coverage of every format against the VFS
nie exe lint                # typed coverage of nie.exe
NIE_GAME_SOURCE="ssh://<game-host>/<game_dir>" nie vfs ls data/common/menu
nie serve                   # HTTP on 8790, /health returns JSON with vfsReady
nie-deploy status --host prd --json   # supervisor, services, live probes, boot hook
```

`<game_dir>` is `[vars] game_dir` of `deploy/supervise.toml`, the host is the production host of `docs/specs/hosts.md`.
Built binaries on the build host: `<build dir>/target/release/{nie,nie-mcp,nie-model-serve}`, with the host and directory from `deploy/build.toml`.

## Rules

- Monorepo: `crates/` is the framework (plus the IEVR core crates still listed as `app` in the
  layering JSON), `plugins/<group>/` the features, `apps/<id>/` the applications; each app has a
  `nie.toml` (name, targets, plugins, ABI exports). A new crate is classified in
  `docs/specs/framework-layering.json` or the layering test fails; a framework crate never names a
  game identifier and never depends on an app crate.
- Reproducible: builds use the pinned toolchain, `--locked`, `SOURCE_DATE_EPOCH` from the commit time,
  `--remap-path-prefix` for the checkout, `CARGO_HOME`, `RUSTUP_HOME` and `$HOME`, and no
  `target-cpu=native`. `just repro` (CI job `repro`) fails on any artifact difference between two
  directories. Never bake a build path or time into a binary (`env!("CARGO_MANIFEST_DIR")`,
  `file!` based paths, timestamps).
- Names: every framework crate, plugin, binary and tool is `nie-<name>` (hyphen, never `nie_`), every environment variable
  nie reads is `NIE_*`; only external standards keep theirs (`HOME`, `RCLONE_CONFIG`, `CLOUDFLARE_*`,
  `GHIDRA_INSTALL_DIR`, `STEAM_COMPAT_*`).
- No host, address or path of this fleet in non-test code: it comes from the environment or from the
  manifests `deploy/build.toml` (build host) and `deploy/supervise.toml` (`[vars]`, the production host).
- Cross-language: `bindings/` is generated by `nie bindgen` from the contract and checked by a drift
  test; the target matrix is `.github/workflows/targets.yml`.
- Rust 2024 workspace, one copy per crate. Every third-party crate comes from crates.io releases,
  versions read live (`curl -A nie https://crates.io/api/v1/crates/<name>`) and declared once in
  `[workspace.dependencies]`; members use `workspace = true`. No vendored third-party code; the only forks are the
  ones named in this file. `cargo shear` stays clean (feature-only dependencies are listed in
  `[package.metadata.cargo-shear] ignored`).
- One crypto and transport stack: TLS is rustls on `rustls-graviola` (`crates/nie-tls`, every binary
  calls `nie_tls::install()` at startup and builds its own configs from `nie_tls::provider()`), SSH is
  russh on RustCrypto (`crates/nie-ssh` client, `crates/nie-sshd` server), git is gix. `deny.toml` bans
  `aws-lc-sys`, `aws-lc-rs`, `ring`, `openssl-sys` and `libssh2-sys`; `cargo deny check bans` must pass.
  The `[patch.crates-io]` entries of `Cargo.toml` are two forks, each dropped when upstream ships the fix:
  steamroom and steamroom-client (aphrody-labs/steamroom branch `nie/no-provider`: v0.3.0 plus upstream commit
  4dd310cb, which hard-codes no provider) and the pingora crates (aphrody-labs/pingora branch `nie/no-ring`:
  tag 0.9.1 on rustls-graviola instead of ring).
- One checkout per fork across `C:\src`: nie declares no submodule and carries no `vendor/` tree. A
  fork nie needs is the sibling checkout of its home repository, or a pinned git dependency when
  no sibling is guaranteed; a new `[patch]` entry needs a documented reason and a removal condition.
- The Zed fork is `aphrody-labs/aphrody` (`C:\src\aphrody`, `crates/gpui*`, `http_client`, `assets/fonts`).
  `gui/`, a workspace of its own (own lock), takes path dependencies on `../../aphrody/crates/gpui*`,
  the one source dependency of nie, because crates.io has no GPUI with a wgpu renderer or a web
  backend; the rule is dropped once zed publishes `gpui_wgpu` and `gpui_web` (forks-sync checks
  crates.io). The root workspace never resolves that path, so a checkout without the fork keeps
  building the core; `just _gpui` clones the sibling (CI, build host).
- LiberNT (aphrody-labs/LiberNT, GPL-3.0 NT kernel and Win32, built only on the build host, never on
  the PC) is a submodule of `fw-nt` (`C:\src\fw-nt/third_party/LiberNT`), not of nie; `just libernt-closure` writes
  `docs/specs/libernt-closure.json` from that checkout. EOS/EAC rule: LiberNT implements only
  documented NT/Win32 behaviour; nothing spoofs Windows to EAC or patches, stubs or skips an EAC
  check; online modes stay off until Epic and Level-5 answer.
- Asterinas (aphrody-labs/asterinas, MPL-2.0 Rust framekernel with the Linux ABI, `branch = main`
  synced from upstream, gap fixes on `nie/*` branches that are also sent upstream as PRs) is the
  submodule `fw-nt/third_party/asterinas`. It supplies the book's `.scml` compat tables read by
  `nie deps audit --syscalls` (default `../fw-nt/third_party/asterinas`). The kernel and the OSDK workspace live in `fw`.
- kitesurf (aphrody-labs/kitesurf, Apache-2.0 browser engine on Blitz, Stylo, Taffy, Parley and boa;
  `branch = nie`, `main` mirrors cloudflare/kitesurf) is a pinned git dependency of
  `crates/nie-browser/host` (its own workspace and nightly toolchain), never of the main workspace.
  Upstream merges go into `nie` by merge commit, never rebase; fixes are PRs to cloudflare/kitesurf.
  `nie-browser deps` reads a kitesurf checkout (`--root`, default `../kitesurf`) and reports each
  patched `browser-*` crate against crates.io into `docs/specs/kitesurf-deps.md`; the engine builds,
  tests and wasm builds run only on `fr1` or in CI, never on the PC.
- Never ship, copy or commit a game asset. Game data is read in place through `nie-assets`
  (`game://`) from a local path, SSH, or an rclone remote. Tests build synthetic fixtures in a temp
  directory.
- A feature outside the nie.exe + VFS core is a plugin: a crate under `plugins/<id>/` that
  implements `nie_plugin::Plugin` (`crates/nie-plugin`) and lists the top-level CLI commands it owns;
  `crates/nie-cli/src/plugins.rs` registers it and its test checks every declared command exists.
- `nie-ffi` builds the library `nie`; its contract-generated part comes from
  `crates/nie-abi/contract.json` and a test fails when the committed files drift.
- Every library crate is also a C-ABI library ("crlib"): `crates/nie-abi/crlib.json` lists every
  workspace member (`crlib`, or `excluded` with a reason), `<crate>/abi.json` is the surface,
  `cargo run -p nie-abi -- --crlib .` writes `include/nie_<id>.h` and `src/abi_generated.rs`, and
  `cargo test -p nie-abi` fails on drift or on a member missing from the list. A new workspace
  crate must be registered there. See `docs/crlib.md`.
- `contract/nie-app.json` is generated by `nie-shell`; the test in `crates/nie-shell` fails when it
  drifts.
- Commit by path on `main`, no AI attribution; `just lint` runs gitleaks, run it before every push; check
  `gh run list -R aphrody-labs/nie` after pushing.
- `.mcp.json` runs `tools/nie-mcp-launch` (standalone zero-dependency crate with its own
  `[workspace]` and lock, so the PC never resolves the workspace graph), which starts the native
  `nie-mcp` server: `NIE_MCP_BIN`, else the newest local build, else the build host over SSH.
- Tooling: repository tasks are `just` recipes over `cargo xtask` (`xtask/`, package `nie-xtask`, light
  dependency set, every dependency from `[workspace.dependencies]`); no shell, Bun or Python script does a
  task of the repository. `.github/workflows` install a pinned `just` and call `just ci-<job>`, nothing else
  runs inline. The standalone tool crates are `tools/nie-mcp-launch` and `tools/nie-perf` (benchmarks);
  `tools/claude` holds the Bun hooks of Claude Code (`.claude/settings.json`); product binaries with their own
  workspace live next to their crate (`crates/nie-browser/host`, kitesurf on nightly).
- nie is a standalone deployed service; consumers call it over HTTP or through the C ABI
  libraries and never embed its Rust. Its source dependencies on other Aphrody repositories are the ones
  named in this file (the `aphrody` checkout of `gui/`, kitesurf, the steamroom and pingora patches); the
  release workflow publishes through `aphrody-labs/ay` (`.github/workflows/release.yml`).
- UI and performance gate: every UI is proven end to end with `test-tui` (TUI), agent-desktop (native) and
  agent-browser (wasm in Chrome), screenshots compared by pixel difference across the targets, and a scripted
  scene measured at 1280x720 with a frame time of at most 8.33 ms (120 fps), or it is not done. CLI and decoder
  speed is measured with `hyperfine --warmup 3 --runs 20 --export-json`, browser and wasm engine speed with
  JetStream; results go to docs/research/log with the environment fingerprint.
- No Docker and no systemd unit for the supervised services: `nie-deploy supervise` runs them
  (`deploy/systemd/` holds the reference units of `nie-comp` and the `nie-link` cache tier for hosts that use systemd).
  The browser UI of `gui/` is the GPUI wasm app on a WebGPU canvas (generated loader and bootstrap only);
  the page of `crates/nie-app/web` (`index.html`, `app.css`, `app.js`, embedded by `just app-pack`) is the one
  hand-written web page.
- Read and write, never read-only: every format nie parses also has a writer with a byte round-trip test on synthetic fixtures, and every tool that views data can edit it (cfg.bin tables, CPK repack, saves, mods). Writes go to an overlay or an output path the user chooses, never into the installed game files in place.
- English, no emoji.

## Gotchas

- Nine text languages ship (`de en es fr it ja pt zh_hans zh_hant`, all translated). The
  `nie vfs cat` preview of a text file prints NOUN_INFO names in Japanese for most of them: compare
  raw bytes before concluding a language is missing.
- Licensing questions go to the Level-5 partner review: list them, change nothing.
