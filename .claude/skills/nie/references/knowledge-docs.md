# Knowledge and docs

Four stores, each with one rule: facts are computed, then cited.

| store | what | command or path |
|---|---|---|
| RE knowledge database | functions, RTTI, xrefs, strings, anchors for `nie.exe` | `var/nie.sqlite`, [re-index.md](re-index.md); MCP `re_query`, `re_function`, `re_coverage` |
| atlas | one index over files, crates, Markdown claims, knowledge digest, forge units, binaries, tools, metrics and the ranked road to 100 % | `nie atlas`, default `var/nie-atlas.sqlite` (`--db`, `NIE_ATLAS`), optional Redis mirror (`NIE_ATLAS_REDIS`) |
| wiki | characters, skills, teams and every decoded table, from the VFS only | `nie wiki`, `nie serve` routes |
| documents | rules, specs, research records | `docs/` |

## Atlas (`nie atlas`, MCP `cli_atlas`, plugin `exe`)

Read-only: `status` (one measured line), `menu` (inventory of the real menu screens and their coverage), `search
<pattern> [--kind doc|symbol|tool|artifact|crate]`, `gaps` (remaining work x weight), `next` (the best-ranked gap as
JSON, for the autonomous loop), `docs` (documents ranked by machine anchoring: addresses, symbols, hashes), `dupes`.
Writes the atlas database: `build` (files, crates, docs, knowledge digest, binaries, tools, metrics, gaps; flags skip
the knowledge digest or the symbol-to-source matching, the costly part), `sync` (and its Redis mirror), `metric`
(record a measurement, a source command is mandatory), `run` (record a step of the loop). Never record a number the
command did not print.

## Wiki (`nie wiki`, MCP `cli_wiki`)

`nie wiki characters|character <key>|skills|skill <key>|teams|team <id>|tables|table <table> <class>|catalog|languages|unsourced|verify`.
Global flags: `--game-dir`, `--lang de,fr` (default every language), `--json`, `-q <substring>`, `--class`, `--limit`,
`--offset`. A character key is a `chara_param` id (`0xXXXXXXXX`), `base-<n>`, a base id or an internal code; a skill is
a `skillID` or a code (`whs00010`); a team is a `belongTeamId`. `nie wiki verify` compares what a wiki serves, field by
field, to the raw decode of the VFS entries. The rules (`docs/wiki.md`): every field is a VFS table value plus its
decoded label, a field with no source is absent and shown as an explicit empty state, references resolve the way the
game does (for example an emblem id is the CRC-32 of the emblem file name), no hardcoded counts, nine text languages,
every page names its VFS path and table. Code: `crates/nie-wiki-vfs`; HTTP: `/v1/wiki/...` and `/wiki` of `nie serve`.

## Documents

- `AGENTS.md`, `STYLE.md`, `README.md`, `MAP.tsv` (`just map`): contract, style, layout.
- `docs/VFS-SPECIFICATION.md`, `docs/NIE-EXE-REVERSE-ENGINEERING.md`: prose maps; re-verify numbers against commands.
- `docs/serve.md` (HTTP service, `NIE_*` variables, game source transports, deploy), `docs/fm.md`, `docs/term.md`,
  `docs/crlib.md` (every library crate as a C-ABI library), `docs/design-system.md`, `docs/adr-*.md`, `docs/wiki.md`.
- `docs/specs/`: official specifications with version, upstream commit and content hash, generated by `nie-specs sync`
  from `sources.toml` (WebAssembly, WebGPU, WGSL, PE/COFF, Direct3D 11.3, DXBC, hosts). `framework-layering.json` is the
  framework or app classification of every crate (the source of truth; `framework-layering.md` lists what is mixed).
  Do not edit generated files.
- `docs/research/README.md`: the research protocol. A result needs a question, the exact commands in the repository, an
  environment fingerprint (commit, toolchain and `Cargo.lock` hash, game buildid and hashes of `nie.exe` and
  `cpk_list.cfg.bin`, host), data named by VFS path and never copied, measured numbers with units and limits.
  Records go to `docs/research/log/YYYY-MM-DD-<topic>.md`. Licensing questions go to
  `docs/research/level5-questions.md` and are listed, not decided.

## Live sources

Versions, APIs and dates are read in the session: `gh api`, `curl -A nie https://crates.io/api/v1/crates/<name>`,
Context7, `rustdoc-md`, then code and manifests before docs. `nie deps audit [--check]` processes external call sites
and tracked crates against `docs/research/log`; the policy files are `docs/specs/*.policy.toml`.
