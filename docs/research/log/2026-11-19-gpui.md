# 2026-11-19: GPUI as the system toolkit of the nie OS

## Question

Can nie take GPUI (zed's UI framework, split into gpui, gpui_platform, gpui_linux, gpui_windows,
gpui_wgpu, gpui_web, gpui_tokio) as its one toolkit for the explorer, viewers, wiki, terminal and
desktop shell, on linux, windows-msvc and wasm32, with crates.io dependencies only, wgpu 30.0.2
and AccessKit accessibility?

## Environment

- Build host fr1: `Linux 7.3.0-10-generic x86_64`, Ubuntu 26.10, `rustc 1.100.0 (0ef1bc386 2026-11-09)`,
  `cargo 1.100.0`, `wasm-bindgen 0.2.130`, Vulkan device `llvmpipe (LLVM 22.1.8, 256 bits)` (lavapipe,
  no GPU), shared host with load average above 50 and `/srv/xbuild` between 96 and 100 percent full.
  Builds ran without sccache (`RUSTC_WRAPPER=`), its server hung under the load.
- Upstream: zed-industries/zed main `b51ffab0153f3372b71d1bd565d48d5203fefe6a` (2026-11-19), latest
  release v1.29.2, toolchain 1.98.1. wgpu on crates.io: 30.0.2 (2026-11-12).
- The fork aphrody-labs/zed is not used as a source: the branch `nie` is generated from upstream.

## Method

1. `cargo xtask zed-branch` (Rust, toml_edit) regenerates the branch:
   - `git archive` of upstream into a scratch directory, then `cargo metadata` for the three targets
     (x86_64-unknown-linux-gnu, x86_64-pc-windows-msvc, wasm32-unknown-unknown) from `gpui_platform` and
     `gpui_tokio`; the union of workspace crates is the closure. The tree is rewritten (members,
     workspace dependencies kept only when a closure crate uses them, `[patch]` and profiles removed)
     and the closure is recomputed until it is stable (round 1: 24 to 24 crates).
   - Dependencies on workspace crates outside the closure (the macOS and iOS backends) are dropped
     from the manifests together with the features that name them.
   - Every git dependency becomes a crates.io one: wgpu and naga `=30.0.2`; the published
     `zed-font-kit 0.14.1-zed`, `zed-reqwest 0.12.15-zed`, `zed-scap 0.0.8-zed`, `zed-xim 0.4.0-zed`;
     `oo7 0.6`, `wasm_thread 0.3`; the `[patch]` entries for async-process, async-task, calloop,
     khronos-egl and windows-capture are dropped (crates.io releases).
   - The run fails when a crate of the closure is not Apache-2.0 or a package outside crates.io remains.
   - The result is one commit on `nie`, on top of the previous tip, so the submodule pin stays
     fetchable and nothing is force-pushed.
2. Closure (24 crates, all Apache-2.0): bench_metrics, collections, derive_refineable, gpui, gpui_linux,
   gpui_macros, gpui_platform, gpui_shared_string, gpui_tokio, gpui_util, gpui_web, gpui_wgpu,
   gpui_windows, http_client, http_client_tls, perf, refineable, reqwest_client, scheduler, sum_tree,
   util_macros, zlog, ztracing, ztracing_macro. `docs/specs/zed-closure.json` has the list.
3. Fixes that exist only at the pinned wgpu revision `cddb2f5d` (473 commits after v30.0.2) and are
   missing in 30.0.2: gfx-rs/wgpu#10230 (Fix issue with surface drop panic, Vulkan, merged 2026-09-12)
   and gfx-rs/wgpu#10348 (Ignore timeouts on wasm, the WebGL resize fix, merged 2026-09-15). Both come
   with the next wgpu release.
4. Source edits (the run fails if upstream moves the text), in the generator:
   - `gpui_wgpu`: `DeviceDescriptor::default_queue` (wgpu trunk, gfx-rs/wgpu#10109) removed in two
     places; `TextureFormat::has_srgb_suffix` (trunk only) replaced by `is_srgb`, which is
     `*self != self.remove_srgb_suffix()` in 30.0.2.
   - `gpui` test window: `a11y_init` calls the activation callback, so headless tests build the
     AccessKit tree and `Window::debug_a11y_tree_json` returns it (upstream tests never activate it).
5. The gui crates live in `gui/`, a workspace of its own, because a path dependency on a missing
   submodule would break the resolution of the root workspace for every other worker and for public CI.

## Second pass (lead's list)

- `nie serve` embedding: `gui/tools/pack-web.ts` output (flat content-hashed files and `manifest.json`)
  is the format of `crates/nie-app`; `NIE_APP_DIST=<dist> cargo build -p nie-cli --bin nie` on fr1 embeds it.
  The binary served `/app/` (HTTP 200, the generated page that loads the wasm-bindgen glue) and
  Chrome 157 headless loaded it from `nie serve` itself on the prd source: `navigator.gpu` present, no
  console error except `/favicon.ico` (404). `?backend=webgl` for the capture, as above.
  The explorer reads `/health` (`936 CPK, 255628 entries` in its status line) and `/v1/vfs/ls`.
  `2026-11-19-gpui-evidence/nie-serve-embedded-explorer-936-cpk.png` is that page; the status line there

  the final picture is `nie-serve-embedded-explorer-936-cpk-final.png`.
- The hand-written HTML of `serve_app.rs`, `serve_wiki.rs` and `nie-wiki-vfs/src/html.rs` is untouched: those
  files belong to other workers and the GPUI wiki is native only, so there is no view that replaces them yet.
- Lua pilot (task 36): `gui/nie-apps/src/lua_tabs.rs`. `nie-lua` runs the game's Lua 5.2 bytecode in the real

- `nie-explore` feature `fm`: files are the `terminal` worker's and uncommitted at HEAD (message sent).

## Not done

- Launcher overlay and notification stack are compile-checked and started in the shell session, but the
  screenshot shows the panel and the explorer only.
- `nie term` as a GPUI window: the terminal surface renders a grid and turns keys into PTY bytes
  (snapshot `terminal.png`); the rio-vt adapter that fills the grid is not written.
- The 3D surface shares no wgpu texture with `nie-render3d`: GPUI has no external-texture API.
- The wiki and the viewer are native only, compile-checked, not run against a game.
- Windows-msvc check of `nie-apps` (C build scripts of tree-sitter and aws-lc-sys need the xwin toolchain).

## Rollback

`git revert` the commit that adds `gui/`; the submodule is removed with `git rm vendor/zed` and the
`.gitmodules` section. The `nie` branch of the fork can be deleted, upstream main is untouched.
