# UE 5.8 / UE 6 architecture mapped to nie performance (2026-11-19)

Scope: which Unreal Engine techniques matter for a data-heavy asset viewer, their Rust equivalents on crates.io
(no fork, no `[patch]`, layering of `docs/specs/framework-layering.json` respected), and the eight changes with the
best gain/effort in the current tree. Every external fact carries its source id (table at the end), fetched
2026-11-19. Anything not verified is marked UNVERIFIED. No build was run on the PC; no number below is a
measurement of nie: `docs/research/log` holds no frame-time or decode-time result (grep for hyperfine/fps/frame
there returns only the gate statement in `2026-11-19-session-handoff.md:41-59` and the unmeasured LTO note in
`2026-11-19-script-lto-deploy.md:76,131,167`). Gains are therefore hypotheses until the gate of each item runs.

## 1. UE features that matter for an asset viewer, and what is confirmed

| UE feature | What it does (source) | 5.8 / UE 6 status | Weight for nie |
|---|---|---|---|
| Nanite | Meshes split into "hierarchical clusters of triangle groups", cluster LOD swapped by view, "runs in its own rendering pass that completely bypasses traditional draw calls", mesh data streamed on demand; DX12 SM6 required, no MSAA/forward/morph targets (E1) | Present in 5.8; fix notes name a Voxel rasterizer and Voxel Foliage (E2). Nothing in them is a renderer change that nie could adopt | Informational only |

UE 5.8 release date: June 17, 2026 (E2 forum post).

Take-away: the UE techniques that pay at nie's scale are the cheap structural ones (GPU timing, compressed
textures with mips, instancing/culling, parallel decode, cached/streamed reads). Nanite, Lumen, VSM, Mass, Iris,
Niagara do not apply to a viewer of single character/stage models with a clay or atlas material.

## 3. What the tree does today (read from source)

- `crates/nie-render3d/src/gpu.rs`: one render pipeline plus one line pipeline (`:630`, `:723`), no MSAA
  (`sample_count: 1`, `:920`, `:999`), atlas textures with `mip_level_count: 1` (`:919`) uploaded as RGBA8 through
  `queue.write_texture` (`:909-960`), draw loop per merged primitive with a bind group switch per texture
  (`:1166-1171`), vertex = 36 bytes f32 plus `u32` indices (`:143-155`, `:880-895`), no frustum culling, no pipeline
  cache, no timestamp queries, `nie_gpu::DeviceRequest` requests no features by default (`crates/nie-gpu/src/lib.rs:45-69`).
- Scene path (`render_scene_to_texture`, `gpu.rs:1472-1575`): one uniform buffer plus bind group per instance,
  `queue.write_buffer` per instance per frame, `draw_indexed(.., 0..1)`: no instancing even for repeated models.
- Web viewer (`web.rs:802-884`): renders the scene into an offscreen target, then a second full-screen blit pass
  to the surface, on every call.
- Textures path: BCn DDS in G4TX, decoded to RGBA8 by `image_dds` (`g4tx_decode.rs:136-189`, `mipmaps: 1`), encoded
  to PNG (`encode_rgba_to_png`, `g4tx_decode.rs:329`, default compression), embedded in the GLB (`assemble.rs`
  png_bytes), decoded again from PNG in `nie-render3d/src/glb.rs:145` (`decode_png`), then uploaded. BC data is
  decoded twice on the way to the GPU (BC to RGBA, PNG deflate and inflate).
- VFS (`crates/nie-formats/src/vfs.rs`): the CPK table of contents is cached by an O(1) LRU under one `Mutex`, then
  `read_file_range` (`:201-214`) does `File::open` + `seek` + `read_exact` into a fresh `Vec` for every entry.
  CRILAYLA decoding (`crilayla.rs:86-247`) is already optimised (block `copy_within`, single bounds check).
  There is no decoded-asset cache, only `DiskCache` for remote bytes (`nie-assets/src/cache.rs`).
- Parallelism: `rayon` is absent from `nie-formats`, `nie-explore`, `nie-render3d`. `menu_predecode.rs` builds a
  per-archive plan but contains no parallel execution.
- Bevy: `plugins/bevy/nie-bevy` only registers AssetLoaders; `nie-render3d/src/bevy.rs:36-52` clones every vertex
  vector per mesh conversion. No ECS-scale workload exists.
- CPU skinning (`apply_pose_cpu`, `glb.rs:550`): no caller outside tests found in `nie-render3d` or `nie-explore`
  (grep this turn), so there is no live animated-skinning hot path to optimise yet.

## 4. Eight changes ranked by (gain) / effort

Parity constraint for every GPU item: the AGENTS.md gate compares screenshots across test-tui, agent-desktop and
agent-browser, and `nie-render3d --verify` already reports a colour gap between CPU nearest sampling and GPU linear
sampling (`gpu.rs:688-690`). Items that change sampling (4, 5) must update the tolerance in the same commit.

|---|---|---|---|---|---|
| 1 | GPU and CPU frame timing: request `TIMESTAMP_QUERY` in `DeviceRequest::with_features` (checked against `adapter.features()`), wrap the viewport pass with `wgpu-profiler` 0.28.0, add a scripted 1280x720 turntable example that prints p50/p99 frame time and first-frame (decode + upload) time as JSON | `stat gpu`, Insights | `crates/nie-gpu/src/lib.rs`, `crates/nie-render3d/src/gpu.rs`, new `crates/nie-render3d/examples/frame_bench.rs` | `hyperfine --warmup 3 --runs 20 --export-json` of the example on fr2; pass = p99 <= 8.33 ms. Ranking basis: items 1 to 4 are small, local, have no new dependency, and 1 unlocks proof for the rest; 5 is the
largest expected VRAM and decode win but needs a format check; 6 only matters for multi-instance scenes
(`examples/story_scene.rs`); 7 and 8 are speculative until item 1 says the main pass is vertex-bound.

Explicitly not proposed: Nanite-style meshlets (bevy `meshlet` is experimental and needs `metis` C), mesh shaders
(native only, fails the browser parity gate), Lumen/VSM/MegaLights (no lighting model to feed), Mass/Iris/Niagara
(no workload), pipeline cache (Vulkan only, 2 pipelines), `basis-universal` (stale since 2023-11-02).
