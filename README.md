# nie

nie is a complete **game engine and static/dynamic recompiler** written in Rust, with a framework and RE/gaming toolchain around it (OS, kernel, POSIX, AI, and ML layers live in `fw`). The runtime side: a virtual
filesystem over local, SSH, rclone and HTTP byte sources, decoders for the Level-5 and CRIWARE formats, a
wgpu renderer for models, textures and sprite sheets, a Bevy asset source (`game://`), the game's Lua 5.2
bytecode run natively, audio and video playback, Steam/Epic launcher integration, and a plugin host. The recompiler & RE side (`plugins/exe/`): PE/binary parsing (`nie-pe`, `nie-sniff`), static recompilation (`nie-recomp`, `nie-re`, `nie-re-core`, `nie-forge`), Win32/runtime shims (`nie-win32`, `nie-trace`), and RE skills (`binary-analysis`, `reverse-engineer-anything`, `static-recompile`). The tool side: a CLI, a JSON API, a
terminal explorer, a GPUI desktop and browser UI, a C ABI with generated bindings (C, C++, Rust, Python, C#,
Go, Bun, Zig), deployment, and builds for Linux (gnu, musl), Windows, macOS, aarch64 and the browser. The
first game on it is Inazuma Eleven: Victory Road: nie reads the installation the player owns and never ships,
copies or commits a game asset. The wiki is one consumer of the engine (`nie-wiki-vfs`), not its purpose.

`docs/specs/framework-layering.json` classifies every crate as framework or app (a test keeps the
framework crates free of game identifiers). Start a new app with `nie new <name> --template
cli|serve|lib|ui|wasm`: it lands in `apps/<name>` (or `--path` anywhere), builds and passes its tests
with no edit, and carries a `nie.toml` (name, targets, plugins, ABI exports).

The IEVR core is two artifacts of the installation:

- the game binary `nie.exe` (reverse engineering: `nie index`, `rtti`, `disasm`, `mem`);
- its data VFS: `data/cpk_list.cfg.bin`, the CPK archives it lists, and the files under
  `data/common/*` and `data/dx11/*`.

Every typed table, CLI command, MCP tool and HTTP route derives from those two. The authoritative
facts are the commands, not this file: `nie --help` lists the commands, `nie plugins` the plugins,
`nie vfs stats` and `nie vfs formats` measure the VFS.

## Game assets

`nie-assets` registers the asset source `game://`. Point it at the installation with
`NIE_GAME_SOURCE` (or a TOML file named by `NIE_ASSETS_CONFIG`):

| source                          | transport                                             |
|---------------------------------|-------------------------------------------------------|
| `D:\Games\ievr`, `/srv/game`    | local files, CPK ranges read in place                 |
| `ssh://host/path`, `sftp://...` | SFTP over `russh`: `~/.ssh` keys, agent, known_hosts, config |
| `r2://remote/bucket/path`       | `rclone.conf` remote read through `opendal` range reads |
| `gdrive://remote/path`, `rclone://remote/path` | `rclone.conf` remote (Google Drive, S3, SFTP, alias) |
| `https://host/path`             | HTTP range requests                                   |

Only the CPK tables and the requested ranges are transferred. `NIE_ASSETS_CACHE_DIR` adds a
size-bounded read-through cache outside the repository. Credentials stay in `~/.ssh` and
`rclone.conf`, never in a URI. The synthetic-CPK test (`cargo test -p nie-assets`) builds its own
archive in a temp directory; `NIE_ASSETS_PRD_SOURCE="ssh://<game-host>/<game_dir>" cargo test -p nie-assets --test prd_stream`
lists and reads a CPK of the real installation over SSH.

## Reproducible builds

`nie repro` exports HEAD twice (`git archive`) into two directories of different depth, builds the
release artifacts with `SOURCE_DATE_EPOCH` from the commit time, `--remap-path-prefix` for the
checkout, `CARGO_HOME`, `RUSTUP_HOME` and `$HOME`, `--locked` and no `target-cpu=native`, and
compares the BLAKE3 hash of every artifact. `docs/specs/repro-manifest.json` records the toolchain,
the `Cargo.lock` hash and the artifact hashes; CI fails on any difference.

## Targets

- Native: Windows, Linux and macOS (CI matrix).
- Web: `nie-wasm` on `wasm32-unknown-unknown`.
- App contract: `cargo run -p nie-shell -- contract` prints `contract/nie-app.json (commands,
  game source settings, build targets).

## Build

Rust 1.100.0 (`rust-toolchain.toml`), every dependency from crates.io. Linux needs the usual Bevy
and winit libraries (ALSA, udev, Wayland, xkbcommon, X11, GL). Heavy builds belong on a build host
or in CI, not on a workstation.
