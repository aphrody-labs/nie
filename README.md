# nie

nie reads Inazuma Eleven: Victory Road from the installation the player owns. It never ships,
copies or commits a game asset.

The core is two artifacts of that installation:

- the game binary `nie.exe` (reverse engineering: `nie index`, `rtti`, `disasm`, `mem`);
- its data VFS: `data/cpk_list.cfg.bin`, the CPK archives it lists, and the files under
  `data/common/*` and `data/dx11/*`.

Every typed table, CLI command, MCP tool and HTTP route derives from those two. The authoritative
facts are the commands, not this file: `nie --help` lists the commands, `nie plugins` the plugins,
`nie vfs stats` and `nie vfs formats` measure the VFS.

## Layout

```
crates/     the core: formats, VFS and typed data, serving, C ABI
  nie-formats      Level-5 and CRIWARE parsers; the VFS (`cpk_list.cfg.bin`, CPK, local, SSH, rclone, HTTP)
  nie-data         typed readers for the cfg.bin tables (`data/common/gamedata`, `data/common/text`)
  nie-explore      format-aware summaries and the domain readers behind `nie vfs` and the HTTP API
  nie-lua          the game's Lua 5.2 bytecode: inspection and host runtime
  nie-assets       Bevy asset source `game://` over the VFS
  nie-render3d nie-gpu   model rendering (CPU rasterizer, optional wgpu viewport)
  nie-cli          the `nie` and `nie-mcp` binaries (`nie serve` is the JSON API)
  nie-model-serve  asset origin: textures, audio, video, models
  nie-wiki-vfs     wiki pages computed from the VFS
  nie-ffi nie-abi  C ABI (library `nie`) and the generator of its contract
  nie-wasm         browser bindings for formats, data and explore
  nie-plugin       the plugin contract
  nie-shell        app contract for the aphrody native shell
  nie-cfgsql nie-sql nie-ocgen
plugins/    features on top of the core; `nie plugins` lists them with their commands
  exe/        nie.exe: nie-re nie-re-core nie-pe nie-index nie-trace nie-forge nie-seed nie-queue nie-camera nie-computer-use
  save/       nie-save
  launcher/   nie-launcher nie-viola (.utmod mods, Viola archives)
  steam/      nie-steam (the game's Steam library and Proton prefix, SQLite index of an install via `nie steam index`)
  bevy/       nie-bevy (game formats as Bevy assets)
tools/         nie-mcp-launch (standalone std-only stdio launcher of nie-mcp for .mcp.json), claude/profile.toml
contract/       nie-app.json and aphrody-store.toml (generated by nie-shell), openapi.json
deploy/         install script, systemd units, run helpers
docs/           service, wiki, design-system and FFI documents
iecode/         git submodules (private): aphrody-labs/iecode-dotnet and aphrody-labs/iecode-cpp
```

The iecode engines are private submodules marked `update = none`, so a plain clone and CI skip
them. With access to aphrody-labs:

```
git submodule update --init --checkout iecode/dotnet iecode/cpp
```

## Game assets

`nie-assets` registers the asset source `game://`. Point it at the installation with
`NIE_GAME_SOURCE` (or a TOML file named by `NIE_ASSETS_CONFIG`):

| source                          | transport                                             |
|---------------------------------|-------------------------------------------------------|
| `D:\Games\ievr`, `/srv/game`    | local files, CPK ranges read in place                 |
| `ssh://host/path`, `sftp://...` | SFTP over `russh`: `~/.ssh` keys, agent, known_hosts, config |
| `r2://remote/bucket/path`       | `rclone.conf` remote read through `opendal` range reads |
| `gdrive://remote/path`, `rclone://remote/path` | `rclone.conf` remote (Google Drive, S3, SFTP, alias) |
| `https://host/path`             | HTTP range requests                                   |

Only the CPK tables and the requested ranges are transferred. `NIE_ASSETS_CACHE_DIR` adds a
size-bounded read-through cache outside the repository. Credentials stay in `~/.ssh` and
`rclone.conf`, never in a URI. The synthetic-CPK test (`cargo test -p nie-assets`) builds its own
archive in a temp directory; `NIE_ASSETS_PRD_SOURCE="ssh://prd/srv/nie/steam/steamapps/common/INAZUMA ELEVEN Victory Road" cargo test -p nie-assets --test prd_stream`
lists and reads a CPK of the real installation over SSH.

## Targets

- Native: Windows, Linux and macOS (CI matrix).
- Web: `nie-wasm` on `wasm32-unknown-unknown`.
- aphrody shell: `cargo run -p nie-shell -- contract` prints `contract/nie-app.json` (commands,
  game source settings, build targets); `-- store` prints the catalog entry the shell merges
  from `$XDG_CONFIG_HOME/aphrody/awesome_gpui_store.toml`.

## Build

Rust 1.100.0 (`rust-toolchain.toml`), every dependency from crates.io. Linux needs the usual Bevy
and winit libraries (ALSA, udev, Wayland, xkbcommon, X11, GL). Heavy builds belong on a build host
or in CI, not on a workstation.
